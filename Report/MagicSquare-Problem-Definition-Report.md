## Executive Summary

4×4 마방진 과제는 “16칸 숫자 퍼즐”이 아니라, **고정 규칙(1~16 각 1회, 행·열·대각 합 동일)에 대한 일관된 판정**과, 선택적으로 **규칙을 만족하는 격자 산출**, 그리고 **반복·자동 검증 가능한 품질 보증**을 목표로 하는 학습·QA 과제로 재정의되었다. 표면 목표(“마방진을 만드는 프로그램”)는 관측 불가·오라클 혼동·실패 시나리오 부재로 부적절하다.

---

## STEP 1 — Observation (관찰)

### 1.1 해결하려는 상황

- **대상:** 4×4 정수 격자, 숫자 집합 {1,…,16}, 합 일치 규칙
- **역할:** QA — 요구·동작·경계를 검증 가능하게 정의
- **프로젝트 상태:** 저장소만 존재, 구현 없음
- **열린 질문:** 생성 vs 검증, 사용자 입력, 오류 처리, 다중 해에 대한 기대

**한 줄 요약:** 수학적 규칙은 분명하나, 소프트웨어가 약속할 동작과 ‘통과’의 증거가 아직 기록되지 않은 출발점.

### 1.2 4×4를 다루는 이유 (관찰)

| 관점 | 관찰 |
|------|------|
| 검증 가능성 | 행·열·대각 검사 규칙이 짧고 자동화 용이 |
| 경계 | 중복, 범위 밖, 빈 칸, 잘못된 합 등 실패 시나리오가 구체적 |
| 규모 | 수동·자동 검증 모두 부담 적음 |
| QA 연습 | 요구 명세, 테스트 설계, 회귀, DoD 연습에 적합 |

### 1.3 학습·시스템 설계 맥락

- **QA:** 유효 격자 정의, 테스트 전략(단위·통합·골든·부정), 품질 속성
- **설계:** 검증 / 생성·표시 책임 분리, 관측 지점(CLI·API·UI)
- **프로세스:** 관찰 → 정의 → 수용 기준 → 설계 → 구현 (현재: 관찰·정의)

---

## STEP 2 — Why #1

### 2.1 가정한 답 (A)

> 사용자·후속 시스템이 **행·열·대각 합이 같고 1~16이 중복 없이 채워진 4×4 격자**를 **신뢰하고 바로 쓸 수 있어야** 한다. “완성”은 수동 합 맞추기·수정 부담을 프로그램에 넘기는 것.

### 2.2 구조적 문제 (A에서 드러남)

| # | 문제 |
|---|------|
| 1 | 완성 ≠ 생성 ≠ 검증 — 주체·과정 불명확 |
| 2 | 유효 해 다수 — 고정 스냅샷 vs 속성 검증 갈림 |
| 3 | 신뢰 근거 부재 — 검증 과정·실패 설명 없음 |
| 4 | 부담 이전 불완전 — 입출력·운영 부담 누락 |
| 5 | 검증만 필요한 니즈와 충돌 가능 |
| 6 | 실패·부분 상태·비기능·DoD 공백 |

---

## STEP 3 — Why #2

**Q:** 왜 단순 계산이 아니라 프로그램인가?

| 관점 | 핵심 |
|------|------|
| 반복 가능성 | 절차·판정의 재현 (출력 숫자 고정과 구분) |
| 검증 자동화 | 오라클을 기계가 매번 적용 |
| 오류 방지 | 전 행·열·대각·집합 제약 누락 방지 |
| 규칙 기반 사고 | 도메인 규칙 → 검증 규칙 → 테스트로 명문화 |

**종합:** 4×4가 어려워서가 아니라, **품질·학습·재현성을 시스템에 고정**하려 함.

**Why #1 + #2:** 사람이 손으로 하던 것을 규칙이 고정된 검증·(필요 시) 생성 과정으로 바꾼다.

---

## STEP 4 — Why #3 (TDD)

### 4.1 TDD를 선택하는 이유

불변 조건을 구현보다 먼저 실패하는 테스트로 고정하고, 구현은 최소 수단으로만 확장.

### 4.2 통제 대상

- 유효성 판정, 도메인 규칙, 경계·부정, 책임 범위, 회귀, (선택) 결정성

### 4.3 불변 조건 (I1~I7)

| ID | 내용 |
|----|------|
| I1 | 4×4 |
| I2 | 값 ∈ {1,…,16} |
| I3 | 중복 없음 |
| I4~I6 | 행·열·대각 합 = 34 |
| I7 | 마방 상수 요약 |

**비불변:** 특정 16개 배치 한 장, 실행마다 동일 배열.

### 4.4 입출력 명확성

- Given/Then이 계약이어야 테스트가 요구·QA 오라클이 됨
- 첫 실패 테스트가 검증 중심인지 생성 중심인지로 범위가 드러남

## STEP 5 — 진짜 문제 정의

### 5.1 표면 문제 (잘못된 정의)

“4×4 마방진을 만드는 프로그램” — 동사 모호, 관측 불가, 오라클 혼동, 실패 없음, QA·TDD 단절.

### 5.2 개선된 정의

> 고정된 4×4 정수 격자에 대해, “1~16 각 1회”와 “모든 행·열·두 대각선 합 동일”을 **일관되게 판정**하고, 필요 시 규칙을 만족하는 격자를 **산출**하되, 산출·판정을 **반복·자동 검증** 가능하게 하는 품질·학습 과제.

| 구분 | 내용 |
|------|------|
| 핵심 | 판정 |
| 선택 | 산출 (산출물은 반드시 판정 통과) |
| 비목표(초기) | 유일 정답 고정, n×n 일반화, 속도·UI 과잉 |

### 5.3 핵심 Invariant (S·V·M·P)

```
S1, S2  →  격자 형태 (4×4, 전 칸 채움)
    ↓
V1, V2  →  값·집합 (1~16, 중복 없음)
    ↓
M1~M4   →  합·대각 (공통 합 34)
    ↓
P1~P3   →  판정·산출 신뢰 (결정적 판정, 위반 시 통과 금지, 산출물 규칙 준수)
```

### 5.4 훈련하는 사고 능력

1. 규칙 분해  
2. 오라클·수용 기준 (QA)  
3. 계약·입출력 (TDD)  
4. 재현·회귀  
5. 문제 정의 비판  

**목표 한 줄:** 규칙·불변·입출력·판정으로 “맞다”를 말할 수 있는 QA·규칙 기반 사고.
