## Executive Summary

PRD v0.2·ECB·Dual-Track SSOT를 기준으로 **FR-01~FR-05 전체**에 대한 RED 테스트 설계표를 작성했다. Track A는 Boundary 입력 검증(E001~E005)·출력 계약(`int[6]`·1-index)·invalid 시 Domain `execute` 0회 격리를 분리했고, Track B는 G0~G3 fixture 기반 Domain Logic(별칭: `find_blank_coords`, `find_not_exist_nums`, `is_magic_square`, `solution`)을 **Domain Mock 없이** 행 단위로 정의했다. 본 세션은 **설계(Track A 문서)** 만 수행했으며, pytest·`tests/`·`src/` 변경은 하지 않았다.

## 프로젝트 계약 (요약)

| 항목 | 규칙 |
|------|------|
| 입력 | 4×4 `int[][]`, `0`=빈칸(정확히 2개), 값 `0` 또는 `1~16`, non-zero 중복 금지 |
| 출력 | `int[6]` = `[r1,c1,n1,r2,c2,n2]`, 좌표 **1-index** |
| 마방 상수 | M = 34 (`MagicConstant` SSOT) |
| Boundary 검증 순서 | null → size → empty count → value range → duplicate |
| invalid 입력 | Failure envelope (Python 예외 아님); `execute` **0회** (U-FLOW-02) |
| Track B | Entity/Control 단위; **Domain Mock 금지** |
