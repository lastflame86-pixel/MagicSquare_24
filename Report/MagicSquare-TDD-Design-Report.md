## 1. Executive Summary

4×4 Magic Square 1차 TDD 사이클은 **마방진 생성이 아니라 규칙 기반 판정(검증)** 을 1순위로 한다. 불변 조건 **S·V·M·P**(및 I1~I7)를 **Red 백로그 8건(RED-01~08)** 으로 고정하고, **입·출력 계약(IN/OUT)** 과 **판정 순서 S→V→M** 으로 Green을 최소 확장한다. 오라클은 **특정 16칸 배치 한 장이 아니라 규칙 집합**이며, 통과 케이스는 **서로 다른 유효 격자 2종** 이상으로 검증한다. **생성·n×n·UI/CLI·성능** 은 이번 사이클에서 제외하며, 생성은 **G1~G3 게이트** 충족 후 2차 사이클에서 Validator 연쇄(P3)로만 도입한다.

## 2. 전제 (문제 정의 요약·참조 문서)

### 2.1 진짜 문제 정의 (한 문장)

완전히 채워진 4×4 정수 격자에 대해 「1~16 각 1회」와 「모든 행·열·두 대각선 합 동일」을 **일관되게 판정**하고, 필요 시 규칙을 만족하는 격자를 **산출**하되, 판정·산출을 **반복·자동 검증** 가능하게 하는 품질·학습 과제이다.

### 2.2 Invariant 계층 (채택)

| 계층 | 한 줄 요약 |
|------|------------|
| **S** | 4×4 격자이며 16칸이 모두 채워져 있어야 한다. |
| **V** | 값은 1~16이고 중복 없이 각각 한 번만 등장한다. |
| **M** | 모든 행·열·주대각·부대각의 합이 같으며, 4×4에서는 공통 합 **34**이다. |
| **P** | 동일 입력 → 동일 판정, 위반 시 통과 불가, 산출물이 있으면 반드시 판정 통과(P3는 2차). |

### 2.3 참조 문서

| 문서 | 용도 |
|------|------|
| `Report/MagicSquare-Problem-Definition-Report.md` | STEP 1~5 문제 정의·I1~I7·비불변 |
| `README.md` | 프로젝트 상태·도메인 규칙 요약 |

### 2.4 TDD 설계 문서 범위

**In scope:** 범위·입출력 계약, Invariant↔테스트 매핑, 전략·Red 백로그, Green/Refactor, AC·DoD, 착수 체크리스트.

**Out of scope:** 코드·알고리즘, 생성(1차), n×n, UI/CLI, 성능 벤치마크, 문제 정의 재논의.

## 4. 입출력 계약 (STEP 2)

### 4.1 입력 계약

| 계약 ID | 입력 형태 | 허용 | 거부·미완성 처리 |
|---------|-----------|------|------------------|
| **IN-01** | 완전 4×4 정수 격자 (16값) | 판정 수행 | — |
| **IN-02** | 빈 칸·null·미지정 | — | `NOT_APPLICABLE`, **S2**, PASS/FAIL 구분 |
| **IN-03** | 범위 밖 값 (완전 16칸) | 수신 | `FAIL`, **V1** |
| **IN-04** | 형식 오류 (비4×4·비숫자 등) | — | `REJECTED`/`NOT_APPLICABLE`, **S1** |
| **IN-05** | 완전 격자 + 중복·집합 위반 | 수신 | `FAIL`, **V2** |
| **IN-06** | 완전 격자 + M 위반 | 수신 | `FAIL`, **M1~M4** (기본: 최초 1개 ID) |

### 4.2 출력 계약

**정책:** `OUT-02`·`OUT-03`에는 **위반 규칙 ID ≥ 1개** 필수. `OUT-01`에는 위반 ID 없음. 위반 시 **PASS 금지(P2)**.

| 계약 ID | 상황 | 출력(관측 가능) | 실패 시 필수 정보 |
|---------|------|-----------------|-------------------|
| **OUT-01** | 통과 | `result = PASS` | — |
| **OUT-02** | 실패 (V/M/P2) | `result = FAIL` | violationIds, 요약(필수); 인덱스(P1) |
| **OUT-03** | 미완성·판정 불가 | `result = NOT_APPLICABLE` | S2/S1 ID, 「유효/무효 판정 없음」 |
| **OUT-04** | 입력 거부 | `result = REJECTED` | S1/형식 오류, 규칙 검사 이전 표시 |

### 4.3 결정성

**예** — 동일 입력 → 동일 `result`·동일 `violationIds`. 검증 결과는 비불변(특정 배치·실행마다 다른 정답)의 영향을 받지 않는다.

## 5. Invariant ↔ 테스트 매핑 (STEP 3)

| Invariant ID | 의미(1줄) | 테스트 유형 | 실패 시 관측 | 우선순위 |
|--------------|-----------|-------------|--------------|----------|
| **S1** | 4×4 구조 | 부정·단위 | S1, 판정 없음 | P0 |
| **S2** | 16칸 완전 | 부정·단위 | NOT_APPLICABLE, S2 | P0 |
| **V1** | 1~16 범위 | 부정·단위 | FAIL, V1 | P0 |
| **V2** | 중복 없음 | 부정·단위 | FAIL, V2 | P0 |
| **M1** | 행 합 34 | 단위·부정 | FAIL, M1 | P0 |
| **M2** | 열 합 34 | 단위·부정 | FAIL, M2 | P0 |
| **M3** | 주대각 34 | 단위·부정 | FAIL, M3 | P0 |
| **M4** | 부대각 34 | 단위·부정 | FAIL, M4 | P0 |
| **M(요약)** | M1~M4 동시 | 통합 | PASS 또는 M 위반 | P0 |
| **I7** | 마방 상수 34 | 단위·통합 | M 요약(선택) | P1 |
| **P1** | 결정성 | 속성·통합 | 2회 호출 동일 | P0 |
| **P2** | 위반 시 PASS 금지 | 부정·통합 | result ≠ PASS | P0 |
| **P3** | 산출물 판정 통과 | *(2차)* 통합 | generate→PASS | P2 |

**비불변 반영:** 통과는 **규칙 오라클**; 유효 격자 **≥2종**; 골든은 「이 배열=정답」이 아니라 「이 배열도 PASS」 회귀 샘플.

## 6. 테스트 전략·책임 분리 (STEP 4)

### 6.1 테스트 피라미드

| 레벨 | 목적 | Magic Square 내용 | 비율 |
|------|------|-------------------|------|
| 단위 | 규칙 격리·속도 | S/V/M 개별, ID 부여 | ~50% |
| 통합 | IN→OUT·순서 | Validator 전체, P1/P2, 유효 2종 | ~35% |
| 속성 | 규칙 유지 | 유효 PASS, 단일 칸 교란 FAIL+ID | ~10% |
| 골든(예시) | 회귀 샘플 | 유효/무효 예시 각 소수 | ~5% |

### 6.2 책임 분리

| 컴포넌트 | 책임 | 하지 않을 일 | 관측 지점 |
|----------|------|--------------|-----------|
| **GridInput** | 입력 정규화·거부/불가 | S·V·M 판정 | parse → OK/REJECTED/INCOMPLETE |
| **MagicSquareValidator** | S→V→M→P 판정 | 파싱·표시·생성 | validate → ValidationResult |
| **RuleCatalog** | 규칙 ID·I1~I7 매핑 | 실행·IO | ID 집합 문서 일치 |
| **ValidationReporter** | OUT 형태 노출 | 판정 변경 | 동일 Result → 동일 직렬화 |
| **MagicSquareGenerator** *(2차)* | 격자 산출 | 최종 판정 | Validator 연쇄 PASS |
| **GridPresenter** *(선택)* | 표시 | 판정 로직 | 출력에 result·IDs |

### 6.3 회귀·CI

**P0 회귀 범주 5개:** (1) S1/S2 형태·완전성 (2) V1/V2 (3) M1~M4 (4) 유효 격자 ≥2종 PASS (5) P1·P2·OUT 구분.

**Merge 차단:** ① P0 전체 실패 ② P1 CI 필수 항목 실패 ③ Red 시나리오↔테스트 매핑 체크리스트 미충족.
