## 1. Executive Summary

Magic Square 4×4 TDD Practice is a **pre-implementation product requirements document** for a pure-logic training system. Given a 4×4 integer matrix with **exactly two blank cells** (`0`), the system discovers blank coordinates, identifies the two missing numbers from `{1,…,16}`, attempts **small-first** then **reverse** placement, validates magic-square invariants (sum **34** on every row, column, and diagonal), and returns a fixed **`int[6]`** result `[r1, c1, n1, r2, c2, n2]` using **1-index** coordinates. This project trains **invariant-based reasoning**, **input/output contract discipline**, **Dual-Track TDD** (Boundary vs Domain), and the **design → test → implement → refactor** loop—not algorithmic difficulty or UI delivery.

---

## 2. Background

Report/1 (Problem Definition) observes that a 4×4 magic square is a bounded domain where rules (1~16 each once, equal row/column/diagonal sums) are short, automatable, and QA-friendly. The surface goal—“build a program that makes a magic square”—is inadequate because it conflates generation, validation, and trust without observable contracts.

This PRD targets **TDD practice before implementation**: learners and reviewers need a single, testable specification for a **2-blank solver** input model (Level 1~5 Planning) rather than a generic puzzle solver. UI, DB, and Web are excluded; execution is console or test-runner centered.

---

## 3. Problem Statement

The product problem is **not** “create any magic square.” The product problem is:

> Complete a **partially filled 4×4 grid** (exactly two blanks) by assigning the two missing numbers such that **verifiable invariants** hold, and return coordinates and values in a **fixed output contract**.

Input/output contracts are central because Given/When/Then tests become the oracle. Without fixed contracts, Boundary validation, Domain logic, and regression protection cannot be traced from concept to component.

## 10. Functional Requirements

### FR-01 Input Verification, Boundary

- **Description:** Validate incoming `int[][]` grid before any Domain resolver executes.
- **Layer:** Boundary
- **Input:** Raw `int[][]` grid reference from caller
- **Processing Rules:**
  - Reject if row count ≠ 4 or any row length ≠ 4 → ERR-BND-001
  - Count cells equal to `0`; reject if count ≠ 2 → ERR-BND-002
  - Reject if any cell ∉ `{0} ∪ {1,…,16}` → ERR-BND-003
  - Reject if any value in `{1,…,16}` appears more than once → ERR-BND-004
  - On any ERR-BND-00x: **do not call** BlankFinder, MissingNumberFinder, MagicSquareValidator, or Solver
- **Output:** `BoundaryValidationResult` with `success=true` or `error_code` ∈ {ERR-BND-001, ERR-BND-002, ERR-BND-003, ERR-BND-004}
- **Acceptance Criteria:** AC-BND-001, AC-BND-002, AC-BND-003, AC-BND-004, AC-BND-ISO-01
- **Error / Exception Policy:** Return structured failure DTO; **do not propagate** uncaught exceptions to caller for expected validation failures (see DEC-002)
- **Related Business Rules:** BR-01, BR-02, BR-03, BR-04
- **Related Test Direction:** Track A — one RED per error code; spy/mock Domain call count = 0
- **Component Candidate:** BoundaryValidator

### FR-02 Blank Coordinate Discovery

- **Description:** Locate the first and second blank cells in row-major order.
- **Layer:** Domain
- **Input:** Grid that passed FR-01 (exactly two `0` cells)
- **Processing Rules:**
  - Scan rows top-to-bottom, columns left-to-right within each row
  - First `0` → first blank `(row0, col0)` 0-index internally
  - Second `0` → second blank `(row1, col1)` 0-index internally
- **Output:** `BlankPair` with `(row0, col0, row1, col1)` in 0-index internal form
- **Acceptance Criteria:** AC-DOM-002, AC-DOM-002b
- **Error / Exception Policy:** Not invoked when FR-01 fails; if invoked, exactly two blanks must exist (precondition guaranteed by Boundary)
- **Related Business Rules:** BR-05
- **Related Test Direction:** Track B — fixed grid with known blank positions
- **Component Candidate:** BlankFinder

### FR-03 Missing Number Discovery

- **Description:** Compute the two numbers from `{1,…,16}` absent from the grid (excluding `0` cells).
- **Layer:** Domain
- **Input:** Grid that passed FR-01
- **Processing Rules:**
  - Build set of present non-zero values
  - Missing set = `{1,…,16} \ present`
  - Return exactly two integers sorted ascending: `small ≤ large`
- **Output:** `MissingPair` with `(small, large)`
- **Acceptance Criteria:** AC-DOM-003, AC-DOM-003b, AC-DOM-003c
- **Error / Exception Policy:** Precondition: FR-01 passed; exactly two missing numbers always exist when exactly two blanks and no duplicate non-zero
- **Related Business Rules:** BR-06, BR-07
- **Related Test Direction:** Track B — DATA-MISS-01 grid
- **Component Candidate:** MissingNumberFinder

### FR-04 Magic Square Validation

- **Description:** Determine whether a **complete** 4×4 grid satisfies magic-square invariants.
- **Layer:** Domain
- **Input:** Complete 4×4 copy with no `0` cells (candidate grid after placement)
- **Processing Rules:**
  - Every value ∈ {1,…,16} and no duplicates
  - Sum of each of 4 rows = 34
  - Sum of each of 4 columns = 34
  - Sum of main diagonal = 34
  - Sum of anti-diagonal = 34
- **Output:** `MagicValidationResult` with `is_valid: bool`
- **Acceptance Criteria:** AC-DOM-004-FAIL-ROW, AC-DOM-004-FAIL-DUP
- **Error / Exception Policy:** Returns `is_valid=false` on violation; does not raise for invariant failure
- **Related Business Rules:** BR-08, BR-09
- **Related Test Direction:** Track B — row-fail grid, duplicate-fail grid
- **Component Candidate:** MagicSquareValidator

### FR-05 Two-Combination Solver and Result Formatting

- **Description:** Try small-first placement, then reverse placement; format success as `int[6]` or return ERR-SOL-001.
- **Layer:** Domain (Solver logic) + Boundary (ResultFormatter for 1-index `int[6]`)
- **Input:** FR-01-valid grid; BlankPair; MissingPair
- **Processing Rules:**
  - **Attempt 1:** place `small` at first blank, `large` at second blank; run FR-04 on copy
  - If Attempt 1 valid → success with `[r1,c1,small,r2,c2,large]` where `(r1,c1)` = 1-index of first blank, `(r2,c2)` = 1-index of second blank
  - **Attempt 2:** if Attempt 1 invalid, place `large` at first blank, `small` at second blank; run FR-04 on copy
  - If Attempt 2 valid → success with `[r1,c1,large,r2,c2,small]`
  - If both invalid → ERR-SOL-001, `SolveStatus.UNSOLVABLE`
  - Coordinate conversion: `r1 = row0 + 1`, `c1 = col0 + 1`, `r2 = row1 + 1`, `c2 = col1 + 1`
- **Output:** Success: `int[6]` length exactly 6; Failure: ERR-SOL-001
- **Acceptance Criteria:** AC-DOM-005-A1, AC-DOM-005-A2, AC-SOL-001, AC-BND-005
- **Error / Exception Policy:** ERR-SOL-001 returned as structured failure; no success array on unsolvable
- **Related Business Rules:** BR-10, BR-11, BR-12
- **Related Test Direction:** Track B — DATA-SOL-A1 (Attempt1 pass), DATA-SOL-A2 (Attempt1 fail, Attempt2 pass), unsolvable grid
- **Component Candidate:** Solver, ResultFormatter, SolveOrchestrator (Control)

## 11. Business Rules / Domain Rules

| ID | Rule (must always hold) |
|----|-------------------------|
| **BR-01** | Input must be exactly 4 rows, each row exactly 4 columns. |
| **BR-02** | Cell value `0` denotes blank; blank count must be exactly **2**. |
| **BR-03** | Every cell value must be `0` or an integer in **1..16** inclusive. |
| **BR-04** | For values in **1..16**, each value appears at most once (duplicates forbidden among non-zero cells). |
| **BR-05** | **First blank** is the cell with value `0` found first in **row-major** scan (row index ascending, then column index ascending). **Second blank** is the next `0` in the same scan order. |
| **BR-06** | Exactly **two** numbers from `{1,…,16}` are missing from the grid (non-zero present values). |
| **BR-07** | Missing numbers are ordered **ascending** when exposed as `(small, large)` with `small ≤ large`. |
| **BR-08** | For `n=4`, magic constant **MAGIC_SUM = 34**; all row, column, main diagonal, and anti-diagonal sums of a valid complete grid equal 34. |
| **BR-09** | A complete grid is magic only if BR-08 holds for all 4 rows, 4 columns, main diagonal, and anti-diagonal simultaneously. |
| **BR-10** | Success output is **`int[6]`** with semantic `[r1, c1, n1, r2, c2, n2]`; array length must be **6**. |
| **BR-11** | Output coordinates **`r1, c1, r2, c2`** are **1-index** (each in **1..4**). Internal 0-index `(row0,col0)` maps to `(row0+1, col0+1)`. |
| **BR-12** | Solver attempt order is fixed: **Attempt 1** assigns `small`→first blank and `large`→second blank; **Attempt 2** (only if Attempt 1 fails validation) assigns `large`→first blank and `small`→second blank. |

## 17. Architecture Overview, High-Level

```
┌─────────────────────────────────────────────────────────┐
│ Boundary Layer                                          │
│  BoundaryValidator │ ResultFormatter │ Error DTO emit   │
└───────────────────────────┬─────────────────────────────┘
                            │ depends
┌───────────────────────────▼─────────────────────────────┐
│ Control / Application Layer                             │
│  SolveOrchestrator — coordinates validate → solve flow  │
└───────────────────────────┬─────────────────────────────┘
                            │ depends
┌───────────────────────────▼─────────────────────────────┐
│ Domain Layer                                            │
│  BlankFinder │ MissingNumberFinder │ MagicSquareValidator│
│  Solver (Attempt 1 / Attempt 2)                         │
└─────────────────────────────────────────────────────────┘
```

| Layer | Responsibility | Must Not |
|-------|----------------|----------|
| **Boundary** | Input validation, error DTO, 1-index `int[6]` formatting | Embed magic-sum logic |
| **Control** | Orchestrate Boundary → Domain; enforce 0-call on Boundary fail | Import UI/DB/Web |
| **Domain** | Pure invariant logic | Import Boundary; perform I/O |

**Dependency direction:** Boundary → Control → Domain. Domain **must not** know Boundary, UI, DB, Web, or filesystem.

## 5. small-first / reverse 테스트 데이터가 구분되어 있는가?

| 항목 | 판정 | 문제 | 개선안 |

| **DATA-SOL-A1 / A2** | **라벨만 구분** | §16.4에 용도는 다르지만 **수치 행렬 없음**, “팀이 수치 확정”, DEC-003 | Appendix에 A1/A2 **속성 표**: Attempt1 결과, Attempt2 결과, 기대 `int[6]` (1-index) |
| **혼동 방지** | **약함** | TP-N-01/02와 DATA ID 연결은 있으나 **동일 격자를 공유하면 안 됨**이 문장으로 없음 | “A1 격자에서 Attempt2는 **반드시 FAIL**” 등 **불변 속성**을 데이터 정의에 포함 |
| **SC-DOM-SOL-001** | **Gherkin만** | Appendix 시나리오는 있으나 **DATA-SOL-A2와 1:1 ID 링크 없음** | Gherkin `Examples` 테이블 ID = DATA-SOL-A2 |

**요약:** **개념적으로는 구분**, **실제로 Red를 쓸 수 있는 수준의 데이터 분리는 미완**(DEC-003).

## 6. 1-index 좌표와 row-major 규칙이 누락되지 않았는가?

| 규칙 | 포함 여부 | 문제 | 개선안 |
|------|-----------|------|--------|
| row-major **첫** 빈칸 | BR-05, AC-DOM-002 | — | — |
| row-major **둘째** 빈칸 | FR-05 문장만 | **BR·Matrix·AC 없음** | BR-05b + AC-DOM-002c |
| 1-index 출력 | BR-11, AC-BND-005 | **0-index→1-index 변환 공식** `(r0+1, c0+1)` 미기재 | §12.2에 변환 규칙 1줄 |
| `r1,c1`이 **어느 빈칸**인지 | Attempt 문장에 의존 | “첫 빈칸=첫 `0`”와 “Attempt1에서 small이 들어가는 칸” **동일 좌표**임을 BR로 고정 | BR-14: `r1,c1` = BR-05 첫 빈칸의 1-index |
| reverse 시 좌표 의미 | AC-DOM-005-A2 | **숫자만 바뀌는지 좌표도 바뀌는지** — 같은 두 칸에 swap인지 명시 | “좌표 쌍은 동일, `n1,n2` 순서만 Attempt2 규칙” 문장 추가 |

**요약:** 첫 빈칸·1-index는 있음. **둘째 빈칸 BR·좌표-숫자 매핑 불변**이 약함.
